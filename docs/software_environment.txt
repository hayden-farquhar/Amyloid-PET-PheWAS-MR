Bash and zsh (macOS-specific portability traps)
-----------------------------------------------
BSD zcat (default on macOS) does not handle gzip streams the same way
GNU zcat does. The sweep_finngen_r12.sh script in code/scripts/ uses
"gunzip -c" explicitly to avoid this. CRLF line endings in pre-deposited
OSF CSVs were handled with "tr -d '\\r'" after "tail -n +2" — this is
also in the sweep script. Tabix has a CWD-dependent behaviour where it
writes .tbi index files to the current working directory regardless of
where the source URL points — the sweep script isolates this with a
"cd $TABIX_CACHE && tabix ..." pattern and a "trap EXIT" cleanup.

Hardware
--------
Local development on Apple M-series laptop (CPU-only; PRS-CS MCMC takes
~3-6 hours single-threaded). All compute is CPU-only — no GPU dependency.

Reproducibility on Linux
------------------------
The pipeline is portable to Linux without modification. Replace `brew
install htslib` with `apt install tabix` or build htslib from source. The
PRS-CS numpy 2 patches are platform-independent. PLINK 1.9 binary is
available for Linux at the canonical Purcell distribution site.

Reproducibility on free-tier Colab/Kaggle
------------------------------------------
The pipeline is CPU-bound, so free-tier CPU runtimes are sufficient. To
adapt for Colab: pin package versions at the top of the notebook
(e.g., `!pip install pyliftover==0.4.1 numpy==2.0.0 scipy==1.14.0`),
gate Drive mounting on `os.path.exists('/content')`, and design each
long cell to be resumable (the Phase 2 locus-MR sweep takes ~2-3 hours
on a single-threaded R worker; checkpoint at each panel × outcome).

Expect approximately equivalent wall-clock on Colab/Kaggle CPU as on a
local Apple M-series with single-threaded R: ~2-4 hours for Phases 1-2 +
3-5 combined, plus ~3-6 hours for PRS-CS MCMC.
